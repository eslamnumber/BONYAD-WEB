# CLAUDE.md — Orientation for AI coding assistants

This file is automatically loaded by Claude Code (and read by other AI tools) when working in this repo. **Read this first, then read only the rule doc(s) relevant to the current task.** Doing this minimizes token use and avoids the "read everything every time" trap.

## What this app is

A Next.js 15 App Router web app for **Bonyad** — a marketplace connecting customers with verified construction/service technicians in Saudi Arabia. Backend is REST.

## The `website-bonyad/` folder

The folder `website-bonyad/` at the repo root holds the **frozen legacy React Native + Expo codebase**. It is **`.gitignore`'d** and never modified — read-only reference for:

- Backend endpoints (`website-bonyad/src/config/api.ts`)
- Auth flow shape (login → validate-token → refresh-token)
- Request/response shapes and field names
- Role gating logic
- Existing translation key inventory

**Never copy UI, JSX, components, styling, design tokens, or visual decisions from `website-bonyad/`.** Production UI is now built directly in the app from the Bonyad identity contract — see **[Production UI design](#production-ui-design)** below. (The legacy Figma-generation workflow in [`docs/figma-to-code.md`](docs/figma-to-code.md) is retained as historical reference only.)

All production UI creation and redesign tasks must use:

- `.claude/skills/bonyad-production-design/SKILL.md`
- `.claude/skills/frontend-design/SKILL.md`
- `docs/design/BONYAD_DESIGN_IDENTITY.md`

**Design is generated in-house — never fetched from Figma.** The Bonyad production-design skill is the **only** design path. For every design task you MUST **skip all Figma-fetch steps**: `get_metadata`, `get_design_context`, `get_screenshot`, `get_variable_defs`, the shallow/deep layer walks, the `visited_nodes` cache, the leaf pixel ledger, and Figma icon/asset export (these are the Figma-fetch portions of rules 16–18, 21). The `figma-*` docs are historical reference and run **solely** when the user explicitly hands over a Figma link and asks to import it. Otherwise the design is composed in-house from [`docs/design/BONYAD_DESIGN_IDENTITY.md`](docs/design/BONYAD_DESIGN_IDENTITY.md) + the `frontend-design` skill. **Skipping the Figma fetch is the only change** — the rest of the workflow (phased planning, backend slices, all verification axes, doc maintenance) is unchanged.

**The design is Claude's own — never mirrored from another Bonyad app.** Compose every generated design from the Bonyad identity contract (tokens / fonts / icons / shared components) + `frontend-design` judgment. **Do NOT use the legacy RN app (`website-bonyad/`) or the iOS app (`bonayd-ios/`) as a visual / UI / design reference** — not their screens, layout, composition, component styling, spacing, or "how the iOS profile looks." Both the RN and iOS apps stay **backend-integration references only** (endpoints / auth / request-response shapes per rule 14) — never visual ones. "Matching" or tracing another Bonyad app's look is a defect — the web design is created fresh within the shared identity.

These design rules apply **only when a task asks you to generate / redesign / restyle a design** — they produce the design layer. **Skipping the Figma-fetch steps changes nothing else:** every non-Figma rule still applies in full to the generated design — phased planning + backend slices (rule 16, minus the Figma-fetch phases), tokens-only (3), logical RTL + the inverted mapping (4), i18n (5), file caps (8), Server-Component-default (9), public-page SSR/metadata/JSON-LD (10–11), env (12), WCAG AA (13), no-invented-icons / reuse the existing `src/components/icons` set (15, 21), data classification static-vs-backend (23), per-endpoint tests (1), doc maintenance (22). ### Mandatory end-of-task rule gate (every generated design)

Before reporting any design task done, run **one** verification pass and post a summary. There are **no per-phase stops** — just this single gate at the end:

1. **Run and paste the output** of `pnpm lint`, `pnpm typecheck`, the relevant `pnpm test`, and `pnpm build`. Never claim green without the output.
2. **Verify every axis** — observe it if a session/preview exists, otherwise reason about it explicitly:
   - **Responsive** — mobile-first base; the 12-width matrix (320 / 375 / 414 / 600 / 768 / 900 / 1024 / 1100 / 1280 / 1366 / 1440 / 1920); no horizontal scroll at any width. **`(app)` dashboard screen-roots are full-width flush per rule 4a — no `mx-auto` / `max-w-*` / `lg:px-8` on the root** (`(main)` public pages keep their centered `max-w`).
   - **Dark mode** — every surface (incl. background/glow layers) from a token with both `:root` and `.dark` values.
   - **RTL _and_ LTR** — logical utilities only; the inverted `en→rtl` mapping; `dir="auto"` on dynamic/punctuated copy only, never on static labels.
   - **A11y (WCAG AA)** — real `<label>`s, `aria-label` on icon-only buttons, visible focus, ≥44px touch targets.
   - **Tokens-only** — no hex/rgb/font-family literal (the one tolerated exception is an arbitrary `shadow-[…rgba…]`).
   - **i18n** — every string via `t()`, keys added to both `en.json` and `ar.json`.
   - **File/function caps** — file ≤200, function ≤50, etc.
   - **Data classification** — backend-driven content is fetched, never hardcoded; pending / empty / error / success states all rendered.
3. **Name the docs touched** per rule 22 — or write "no doc update required" with the reason.

See [`docs/task-workflow.md`](docs/task-workflow.md) §Generated-design end-of-task gate for the report template.

## Non-negotiable hard rules (skim before every task)

These are violated most often. Memorize them:

> **Design-task override — generate, don't fetch from Figma.** For any design generation / redesign / restyle task: **skip every Figma-fetch step** — rule 16's Figma phases (`get_metadata` / Phase 0.5 skeleton scan / Phase 5 layer-walk + leaf pixel ledger), rules 17 & 18 in full (layer-tree walk, screenshot ban, pixel-ledger), and the "export from the Figma node" instruction in rules 15 & 21. Generate the design in-house per §Production UI design. **Everything else still binds** — phased planning + backend slices (16), tokens (3), RTL (4), i18n (5), file caps (8), a11y (13), no-invented-icons / reuse the existing icon set (15, 21), data classification (23), tests (1), docs (22) — and every generated design ends with the **mandatory end-of-task rule gate** in §Production UI design (responsive 12-width · dark · RTL+LTR · a11y · tokens · i18n · lint/typecheck/test/build · doc note).

1. **No `fetch()` outside `src/lib/api-client.ts`.** Always go through a TanStack Query hook in `features/X/api/`. **Strict request schemas, permissive response types** — request bodies use zod, response shapes use a TS `type` (never `z.enum` on a backend-controlled string field, never a strict response schema passed to `apiClient`). Strict zod on a response surfaces as a misleading "Something went wrong" the day the backend adds an enum value. See [`docs/api-and-auth.md`](docs/api-and-auth.md) §Schema strategy. **Every new `features/X/api/*.ts` ships with a sibling `*.test.ts` in the same PR** covering: (a) happy path — fetcher returns the parsed result and the request body matches the RN call site; (b) one representative 4xx that surfaces as `ApiError` with `messageEn` / `messageAr` / `errorCode` populated; (c) every special-state branch (pending / OTP / `errorCode`-driven redirect / phone-normalisation / etc.). Form tests do NOT satisfy this rule — they exercise the integration, not the fetcher's branching. See [`docs/testing.md`](docs/testing.md) §Per-endpoint tests.
2. **No endpoint string literal outside `src/config/endpoints.ts`.** Mirror endpoints from `website-bonyad/src/config/api.ts`. **To compare against or find anything in the frozen RN app, the entry point is [`docs/rn-call-site-index.md`](docs/rn-call-site-index.md) — a generated map of every `API_ENDPOINTS.<GROUP>.<KEY>` constant → its path → the exact call-site `file:line` (`services/` ranked first, where the request body + response field reads live). Look up the constant there, then `Read` ONLY that file at that line range (`offset`/`limit` ≈ ±15 lines). Grepping `website-bonyad/` blind, or reading a whole screen file to extract a handful of field names, is a defect — it burns the tokens the index exists to save.** The index is regenerated, never hand-edited, with `pnpm gen:rn-index`; because the legacy folder is frozen it does not drift. Only when a constant is absent from the index (or marked _(defined, no RN usage)_) do you fall back to grep — then regenerate so the map covers it. Before adding a new endpoint integration: `curl` the real backend for ≥3 response cases (success / 4xx / edge) and copy field reads from the index's mapped call site — never guess field names. See [`docs/api-and-auth.md`](docs/api-and-auth.md) §Before adding any new endpoint integration and [`docs/rn-call-site-index.md`](docs/rn-call-site-index.md).
3. **No hardcoded colors, hex, RGB, or font-family.** Use Tailwind utilities backed by tokens in `src/styles/tokens.css`.
4. **No physical Tailwind direction utilities** (`ml-*`, `mr-*`, `pl-*`, `pr-*`, `left-*`, `right-*`, `text-left`, `text-right`). Use logical (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`). **Default to `-end` over `-start` for card / content alignment** — the direction mapping is **inverted** (`en → rtl`, `ar → ltr`) per `LOCALE_DIRECTION` in `src/types/locale.ts`, so `-end` resolves to **right in Arabic, left in English** (the design is authored RTL-first — Arabic-primary market — so content anchors to the inline end and mirrors automatically when the locale toggles; this is a product decision, not a Figma artifact). Never read `locale === 'ar'` directly — go through `LOCALE_DIRECTION` or logical CSS. Directional icons (chevrons, back/forward arrows) use a single `ChevronRight` and a single flip class — never a `dir === 'rtl' ? ChevronLeft : ChevronRight` conditional. The flip variant depends on CTA intent: **`ltr:-scale-x-100` for forward chevrons** (next / breadcrumb / pagination — arrowhead points in the reading direction) and **`rtl:-scale-x-100` for inward chevrons** (Learn more / View more pills where the arrow trails the label and points back toward the text). Pick per the CTA's own intent (no Figma to consult on a generated design) — see [`docs/i18n-and-rtl.md`](docs/i18n-and-rtl.md) §Directional icons. **Visuals mirror by default in `en`** — every raster image (`<Image>` / `<img>`) AND decorative SVG illustration (`<Pillar…Illustration>`, blob / swoosh / background artwork) carries `rtl:-scale-x-100` (the `rtl:` variant fires in `en` under the inverted mapping) so the RTL-first composition mirrors with the layout; opt out (omit the class) ONLY for logos, text-bearing graphics, faces, and oriented maps/charts. The flip class lives on the visual element itself — except when it already has its own transform (`rotate-*` / `-scale-y-*`), where it goes on the illustration's own positioning container (two `scale-*` utilities merge into one point-flip). Never on a shared layout wrapper that holds text. See [`docs/i18n-and-rtl.md`](docs/i18n-and-rtl.md) §Visuals. **Translated leaf text** (`<h1>`–`<h4>`, `<p>`, `<li>`) whose `t(...)` value contains leading/trailing weak punctuation (`?` `.` `!` `:` `،` `؟`) MUST carry `dir="auto"`, or the punctuation floats to the visual start in `en` (e.g. `?work` / `.executing easily`) — see [`docs/i18n-and-rtl.md`](docs/i18n-and-rtl.md) §Heading + paragraph bidi. **Conversely — and this is the most-repeated bidi mistake — a static `t(...)` UI label WITHOUT weak punctuation (section heading, field label, button, caption) must NOT carry `dir="auto"`.** On the inverted mapping, `dir="auto"` resolves the element to its _text-language_ direction (English → `ltr`), so its `text-end` lands on the **opposite physical side** from sibling body content that follows the document `dir` — the heading sits flush against the wrong edge (right heading + left body in `en`, mirror in `ar`). `dir="auto"` is opt-in for **dynamic/user-generated content** (titles, descriptions, names, user-typed values) **or** punctuated translated copy only, and pairs with `text-start`, never `text-end`. A heading that aligns opposite to the body it titles = a stray `dir="auto"` on a static label (the job-offer detail headers regression). See [`docs/i18n-and-rtl.md`](docs/i18n-and-rtl.md).
5. **No user-facing string in JSX.** Always `t('namespace.key')` from `react-i18next`.
6. **Features cannot import from other features.** Lift shared code to `src/components/`, `src/hooks/`, `src/utils/`, etc.
7. **No `react-native`, `react-native-web`, `expo-*`, or `nativewind`** anywhere. The legacy app at `website-bonyad/` is **reference only — never copy from it directly**.
8. **File ≤ 200 lines, function ≤ 50 lines, complexity ≤ 10, nesting ≤ 4, params ≤ 4, JSX depth ≤ 5. ESLint-enforced. NO EXCEPTIONS.** This applies **before you write the first line**, not as a lint cleanup pass. Concretely, the AI MUST: (a) include "extraction points" in the Phase 0 plan whenever a file will plausibly exceed 150 lines or a function 40 (the soft thresholds — extract earlier, not at the cap); (b) if a `Write` or `Edit` produces a file that would cross the cap, STOP and extract before continuing — never ship code that fails the lint cap with intent to "fix later"; (c) when a sibling file is already at the cap (e.g. existing 203-line file), the AI's first move is to refactor it down before adding the new code, in the same PR; (d) test files have a 400-line cap; (e) the exemption list (`src/styles/tokens.css`, `src/locales/**`, `src/config/endpoints.ts`, generated files) is closed — no other file is exempt. Extraction patterns are documented in [`docs/file-size-limits.md`](docs/file-size-limits.md) §What to do when you hit a limit. Gaming the limits with `helpers-1.ts` / `part-a.ts` is itself a defect; each split must have a clear name and a single responsibility.
9. **Server Component by default.** Add `'use client'` only at the leaf component that needs hooks/state/events.
10. **Every public page needs SSR + metadata + JSON-LD.** See [`docs/seo-and-ai-readability.md`](docs/seo-and-ai-readability.md).
11. **JSON-LD must be HTML-escaped before `dangerouslySetInnerHTML`** and carry the CSP nonce. Use the `<JsonLd>` helper, never inline. See [`docs/security-headers.md`](docs/security-headers.md).
12. **No `process.env.X` outside `src/config/env.ts`.** All env access goes through the zod-validated `env` export. See [`docs/deployment-and-env.md`](docs/deployment-and-env.md).
13. **WCAG 2.2 AA target.** No `outline: none`, every icon-only button has `aria-label`, every form input has a real `<label>`. See [`docs/accessibility.md`](docs/accessibility.md).
14. **The legacy RN app at `website-bonyad/src/` is backend-integration reference ONLY** — read it to learn endpoints, auth flow, and request/response shapes. **Never copy UI, JSX, styling, components, or design decisions.** The **iOS app at `bonayd-ios/`** is treated the same — readable for backend-integration shapes (some endpoints mirror its services), but **never a design/visual reference**. **Every generated design is Claude's own**, composed from the Bonyad identity (tokens / fonts / icons / shared components) + the `frontend-design` skill — never mirrored, traced, or "matched" from the RN or iOS app's screens, layout, composition, or styling. See §Production UI design + [`docs/migration-notes.md`](docs/migration-notes.md).
15. **No invented icons.** Every icon is an SVG exported from Figma, placed in `src/components/icons/`, with `currentColor` fills/strokes. `lucide-react` is only allowed for system glyphs whose default form matches the design. See [`docs/figma-to-code.md`](docs/figma-to-code.md).
16. **Every non-trivial task is split into phases with verification gates, and HIGH-risk sections are split into sub-sub-phases per component variant.** Phase structure: **Phase 0 (cheap plan)** = `get_metadata` on the top frame only + tentative risk score per section + static/backend classification. STOP. **Phase 0.5 (skeleton scan)** = depth-1 shallow walk per section root, ALL sections fanned out in one parallel message + `get_variable_defs` on top frame. Confirms/promotes risk scores (truncation, ≥3 variant children, ≥5 background layers at depth 1, state-variant suffixes → auto-promote to HIGH), locks sub-sub-phase splits, seeds the background-layer registry, produces the file/endpoint/token/asset/parallel-dispatch lists, populates the session `visited_nodes` cache with section roots. STOP. **Phase 1** = backend integration as **vertical endpoint slices** — optional infra sub-phase (1.0: auth/session, proxy, middleware, apiClient routing) then one gated slice per endpoint (1a, 1b…), dependency-ordered and parallel-where-safe, each shipping schema+fetcher+hook+test+MSW together (absorbs the old "Phase 2 = hooks"; see [`docs/task-workflow.md`](docs/task-workflow.md) §Backend integration). **Phases 3–4** = assets+tokens, route shell. **Phase 5** = section-by-section build with deep recursive BFS to leaves + leaf pixel ledger + 5-axis gate per sub-phase. HIGH-risk sections sub-sub-phase per component variant (5a.1, 5a.2 …) with per-component gates. Triggers for HIGH (any one): ≥3 cards with different content per card, nested complex components, MCP `get_design_context` truncated on section root, Figma state variants, ≥5 distinct background layers. **Phases parallelize independent work** per [`docs/parallel-execution.md`](docs/parallel-execution.md) — Phase 0.5's section-root fan-out is the single biggest batch; sibling layer fetches at the same depth in Phase 5 are MANDATORY parallel; icon exports + independent endpoint slices all run concurrently. Sections themselves NEVER run in parallel — one section per sub-phase, one gate at a time. After each phase / sub-phase / sub-sub-phase, produce a gate report and **STOP** — do not auto-continue. See [`docs/task-workflow.md`](docs/task-workflow.md).
17. **Read the Figma layer tree via two walks — shallow in Phase 0.5 and deep recursive BFS to every leaf in Phase 5. The screenshot is BANNED as a code-derivation source.** Per [`docs/figma-layer-walk.md`](docs/figma-layer-walk.md): the **shallow walk** (Phase 0.5) is one `get_design_context` per section root, no recursion — all sections fanned out in one parallel message. The **deep walk** (Phase 5, per section) is recursive: every non-leaf node (FRAME / GROUP / INSTANCE / COMPONENT / SECTION / BOOLEAN_OPERATION) gets its own `get_design_context` call — recursion is always-on, not "only on truncation." Treating an `INSTANCE` as a leaf is the most common defect; instances frequently have overridden children. Both walks write to a **session-wide `visited_nodes` cache**; Phase 5's deep walk MUST consult the cache before fetching — section roots cached by Phase 0.5 are reused, never re-fetched. Maintain `pending_nodes` and `visited_nodes`; the section is not "walked" until `pending_nodes` is empty. Gate report includes cache hits, cache misses, `total_nodes_visited`, `leaf_count`, the full visited-node list, and the assertion `total_nodes_visited + leaf_count >= metadata.descendant_count`. **Sibling fetches at the same depth are MANDATORY parallel** (one message, multiple `get_design_context` tool calls) — sequential siblings are a defect, not a slowness ([`docs/parallel-execution.md`](docs/parallel-execution.md)). Background layers (section fill, gradients, blur blobs, decorative shapes, image fills) are first-class — every one is walked, paired, rendered, and **appended to the session background-layer registry** (seeded in Phase 0.5, grown in each Phase 5 sub-phase, audited at Phase 7). Pair every layer with kept / inlined / dropped — no silent skips; dropped layers listed in the gate report with a reason. The screenshot may be opened ONCE per section as a sanity reference only; any JSX whose values cannot be traced back to a layer property or token is a defect.
18. **Pixel-perfect Figma matching is mandatory, verified per section (or per component variant on HIGH-risk sub-sub-phases) on 5 axes, against a leaf pixel ledger — not eyeballed.** Enumerate every section as a node ID in phase 0 with its tentative risk score (confirmed/promoted in Phase 0.5); build one section/component at a time; for each, run the deep recursive BFS layer walk to every leaf, **then produce the leaf pixel ledger** — a flat per-leaf table of `leaf_id → property → value → source` covering every box-model / typography / color / geometry / effect / background-layer property the layer defines, sourced from `get_design_context` or `get_variable_defs` (never the screenshot, never inferred from a sibling). **Every CSS value in the JSX must trace back to a ledger row** — values with no ledger row are invented and are a defect. Then verify (a) layer fidelity vs the enumerated layer list — every kept layer rendered, every dropped layer absent, every background-registry row corresponds to a visible element, no untraceable wrappers, (b) computed styles **vs the ledger** including section backgrounds, gradient stops + angle + positions, decorative blur blobs, background images (real exports under `public/images/bg/`, never a CSS gradient substituting for an image fill) — a computed style with no ledger row OR a ledger row whose value differs from the computed style is a fail, (c) RTL mirror, (d) dark mode (every surface incl. background layers from a token with both `:root` and `.dark` values), (e) responsive at the 12-width matrix per [`docs/responsive-verification.md`](docs/responsive-verification.md) (320 / 375 / 414 / 600 / 768 / 900 / 1024 / 1100 / 1280 / 1366 / 1440 / 1920) with hardcoded-coordinate background blobs gated behind `xl:`. See [`docs/figma-to-code.md`](docs/figma-to-code.md) §Pixel-perfect verification and [`docs/figma-layer-walk.md`](docs/figma-layer-walk.md) §Leaf pixel ledger.
19. **Every token in `:root` MUST have a `.dark` counterpart in `src/styles/tokens.css`.** No silent skips. Dark mode is verified per section, not at end-of-screen. See [`docs/theming.md`](docs/theming.md) §Rules rule 7.
20. **Mobile-first ALWAYS — every section's base classes target 320 px, and the per-section gate verifies the FULL 12-width matrix.** No hardcoded pixel widths/heights on layout containers at the base level (`w-[1200px]`, `h-[622px]`, `max-w-[1440px]` — banned). Desktop Figma pixel sizes appear ONLY behind `md:` / `lg:` / `xl:` variants with a mobile-first base (`w-full`, `min-h-[…]`). Decorative absolute-positioned elements with hardcoded coordinates (`absolute start-[Npx] top-[Npx]`) must be `hidden lg:block`. No `overflow-x-auto` carousels of fixed-width cards — use responsive grids so every card is visible at every breakpoint. **Exception (mobile-only scroll-snap):** a designated section MAY use a horizontal scroll-snap row on the base breakpoint only, reverting to a responsive grid at `sm:`+ — implemented with CSS grid (`grid-flow-col auto-cols-[~78%] snap-x snap-mandatory` → `sm:grid-flow-row sm:grid-cols-*`), NOT a `flex … overflow-x-auto` row of `w-[Npx]` cards, with each card full-content (no truncated copy) and the next card peeking. The Find-a-service (Browse) section uses this. **Verify at 320 / 375 / 414 / 600 / 768 / 900 / 1024 / 1100 / 1280 / 1366 / 1440 / 1920** per [`docs/responsive-verification.md`](docs/responsive-verification.md) (the old 3-checkpoint sample misses Windows-laptop-1366, narrow-laptop-1100, and the 900 md→lg crack — all real regressions). Body copy stays `text-base` — never fluid. Use `clamp()` for headings only when discrete scale jumps look bad; use container queries when a component lives in multiple layout contexts. See [`docs/responsive-design.md`](docs/responsive-design.md) §Hard rules + §Anti-pattern catalogue.
21. **Icons are the exact SVG export from the Figma node — never redrawn.** Same `viewBox`, same path data, same dimensions. The only allowed edits are replacing hardcoded `fill`/`stroke` with `currentColor`, stripping placeholder `<title>`/`<desc>`, and whitespace reformatting. Filename = Figma node name in kebab-case. If the export looks wrong, fix the Figma file; do not patch the SVG. See [`docs/figma-to-code.md`](docs/figma-to-code.md) §Icons.
22. **Every PR that adds or moves a feature / endpoint / token / icon / env var / shared component MUST ship the matching architecture-doc edit in the same PR.** Doc drift is review-blocking. The phase-gate report names the doc files touched (or "no doc update required" with a reason). See [`docs/doc-maintenance.md`](docs/doc-maintenance.md).
23. **Every Figma section is classified as static or backend-driven in Phase 0 — backend-driven content is never hardcoded.** If a section renders an instance of a backend entity (subscription plan, service, technician, project, blog post, success story, FAQ, stat counter, featured item, badge) OR the legacy RN app at `website-bonyad/src/` already fetches it from `website-bonyad/src/config/api.ts` OR the content could conceivably change without a code deploy OR the Figma frame shows a repeating card with editorial cardinality — the section is **backend-driven**. Backend-driven sections REQUIRE: (a) Phase 0 names the endpoint (mirroring `website-bonyad/src/config/api.ts`) and the RN call site; (b) Phases 1 + 2 (schema + fetcher + sibling `*.test.ts`) complete BEFORE the section's Phase 5 sub-phase starts — never build the UI against a hardcoded placeholder array "to wire up later"; (c) data fetched in the RSC and passed as a typed prop for public/SEO pages (e.g. `src/app/(main)/for-pros/page.tsx` → `<TechPricing plans={plans} />`), or via the TanStack Query hook for interactive/authenticated pages; (d) pending / error / empty / success states all rendered (empty state via locale copy, never a hardcoded fallback array); (e) localised fields read via `LOCALE_DIRECTION[locale]`, never `locale === 'ar'`. The gate report names the endpoint consumed, where it was fetched, and confirms no hardcoded fallback. When in doubt, the answer is backend-driven — static is the rare branch. See [`docs/section-data-classification.md`](docs/section-data-classification.md).
24. **Read the docs before you search the codebase.** The moment you're about to `grep` / `glob` / `Explore` / fan out a subagent to learn _how this repo does something_ — a convention, where a file or folder belongs, a component pattern, a naming rule, whether a shared util/hook/component already exists — STOP and first read the relevant topic doc through the [`docs/README.md`](docs/README.md) index. **Architecture / folder placement** → [`docs/folder-structure.md`](docs/folder-structure.md); **anything about a component** (the primitive → shared → feature 3-tier hierarchy, where it lives, its props, reuse vs. lift, SOLID) → [`docs/components.md`](docs/components.md); other topics via the index table above. The docs are the source of truth and are far cheaper than a blind sweep — a repo-wide grep "to see how it's usually done" is a defect when the answer is one doc away. Only drop to grep / `Explore` when the doc genuinely doesn't answer it, and when you dispatch a subagent for a convention, instruct it to read the doc first too. If you had to search because the doc was missing or wrong, fix the doc in the same PR (rule 22). _Locating a specific symbol or file you already know exists is ordinary searching — this rule governs discovering conventions and architecture, which live in `docs/`, not at the end of a grep._

## How to work efficiently

- **Don't grep the whole repo for conventions** — they're in `docs/` (hard rule 24). Before searching, read the relevant topic doc via the [`docs/README.md`](docs/README.md) index: architecture / folder placement → [`docs/folder-structure.md`](docs/folder-structure.md), components → [`docs/components.md`](docs/components.md). Read it once; grep only when the doc doesn't answer it.
- **Don't re-read `ARCHITECTURE.md`** — it's a thin redirect. Go straight to `docs/`.
- **Don't read the legacy `website-bonyad/src/` codebase for patterns** — only for endpoint paths, auth flow, i18n keys. And don't grep it to _locate_ those: [`docs/rn-call-site-index.md`](docs/rn-call-site-index.md) already maps every endpoint constant to its exact `file:line`. Read the map, then open ONLY the mapped range.
- **Use the templates** in `docs/state-management.md` and `docs/forms-validation.md` as copy-paste starting points.

## Per-folder hints (only the non-obvious ones)

- `src/app/` — **routes only.** Logic lives in `src/features/`.
- `src/components/ui/` — **shadcn/ui primitives only.** Don't put app-specific things here.
- `src/features/<f>/api/` — **one file per endpoint**, exports fetcher + query-key + hook.
- `src/features/<f>/schemas/` — zod schemas; types are derived with `z.infer`.
- `src/config/endpoints.ts` — **don't drift from `website-bonyad/src/config/api.ts`**. They must mirror.

## When you're unsure
